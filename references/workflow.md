# 研究工作法

此文件规定研究判断，不规定报告格式。根据任务规模选择必要步骤；不要把流程走完当作回答用户的问题。

## 1. 从用户问题出发

用一句话写出“谁想知道什么，为什么需要这个答案”。区分对象或关系格局、比较、观点与经验、变化与事件解释、原因或机制、机会探索及具体决策；只有后者需要写出选项、标准和决定时间。拆成少数会改变答案的问题。为每题记录：目前假设、可能反证、合格证据、所需对象与概念、分析方法、回答状态。不要为凑模板而添加与问题无关的规模、趋势、主体或渠道分析，也不要把探索性任务强行改成决策裁决。

先判断交付性质：纯唤醒按入口返回用法提示；只求单一事实或轻量即时解释、无需选取证据和综合成品时直接回答。凡需选取或整合证据并交付研究报告，不论研究主题、对象或来源数量、是否付费、用户是否明确写出“报告”，都先展示一屏研究方案并等待认可。单一对象、单一来源或可快速调用工具都不构成跳过方案的理由。方案前只解析用户已给的对象、链接和约束，读取本地指引与工具契约；不抓业务资料，不创建采集任务。

先做研究决策审计。根据本次问题考虑目标、对象边界、地域或人群、平台或来源、时期、比较关系、读者用途、证据深度、投入边界和交付形式；这些是发现未知的视角，不是逐项发问的表单。把信息分成四类：用户已明确；可从上下文可靠推定；缺少后会改变对象、来源或解释方向的必须项；不影响研究正确性且有合理默认值的偏好。只询问必须项和确实需要用户取舍的偏好，不重复询问已知内容。推定条件与默认值写入方案供用户发现误解；必须项未解决时不开始取数。

方案要让用户能决定：本次回答什么问题；研究对象、地域、时期、适用主体和比较边界；拟用证据及核验、分析方法；资料选取与停止条件、预计调用/费用或工作量；交付“仅 Markdown（默认）／Markdown＋HTML”。需要新增资料且用户未限定范围或深度时，提供精简、推荐、深入三档。各档说明本任务会核验哪些来源与证据单元、覆盖什么范围、可计数时的目标数量、预计投入，以及扩大范围可能改变的判断。证据单元由问题决定，可以是法规版本、统计序列、研究文献、事件记录、访谈或平台内容；不为所有任务套用平台数和评论数，也不虚构免费研究的 Credits。用户已明确指定范围、数量或预算时直接采用并说明其充分性；只整合已给资料时说明不新增取样和费用，不为凑形式再列三档。

宿主支持结构化选择时，优先把数据深度、分析用途、交付格式和其他相互独立的决定分别呈现，选项必须由本次任务生成；不能用一个自由文本回答承载多个容易漏答的决定。若无结构化选择能力，使用编号清楚、可一次回复的紧凑格式。收到回复后重新检查四类信息：只回答部分问题时，仅补问尚未解决的必须项；偏好项可采用已说明的默认值。选择档位或格式不自动补全其他必须项。取数前用简短确认摘要回显目标、对象与边界、所选深度、来源与方法、停止条件、交付、推定条件和默认值；用户认可后执行。计划内探索与补证可调整具体查询，不反复确认；只有研究目的、来源范围或费用边界实质扩大时再征询。同一方案已获认可时不重复确认。

需要保存取证材料、计算结果或报告时，先为该研究创建独立目录；纯唤醒和不保存材料的即时回答不创建。运行本 Skill 的[任务目录脚本](../scripts/create_run.py)：`python <Skill目录>/scripts/create_run.py --topic <脱敏短主题>`，默认在当前工作区的 `analysis-runs/` 下生成 `YYYYMMDD-HHMMSS-主题-随机ID/`；用户指定交付目录时以 `--runs-root` 指向该目录。主题只用概括性研究词，不传客户姓名、账号 ID、敏感内容或整句查询。脚本不可用但宿主能写文件时，按相同命名规则创建唯一目录。当前任务的原始资料、编码、计算、QA 和最终 `report.md`／`report.html` 只放入当前目录；不扫描、读取或默认复用其他任务目录的数据。用户明确要求续接某任务时，先核对其路径和范围再使用。

## 2. 先规划证据，再规划工具

为每个问题建立内部“证据路线”：主张或决策 → 对象、概念与所需证据 → 可用来源 → 获取层级（索引、列表、详情、全文或原始数据）→ 抽样与计算 → 缺失时的替代来源。按问题选择原始记录、官方资料、统计、研究、当事方陈述、独立调查、平台内容或其他适用材料；例如（仅作说明），政策效力应回到现行原文，技术能力需要规格、测试或实现证据，商品与社媒内容可由 RealTrace 或公开页面取得。检索范围由研究问题决定，不受现有 MCP 平台列表限制。不要让某个工具提供什么就决定报告研究什么。

完成初步发现后做第二次来源充分性审查：关键问题是否都有适合的证据类型，是否覆盖重要相反观点与不同主体，对象层级、地域和时期是否匹配，关键材料能否深入到详情或原文，来源之间是否只是重复转述。缺口由尚未解决的问题决定；自主扩展新的平台、公开资料、权威原始发布或可靠二手来源，不以平台数、链接数或记录数代替充分性。

需要扩展资料时先有界发现，按研究问题排除无关、重复或不适用的对象，再核对原文、版本与口径。详情或原文不可达时，依次寻找同一材料的可访问版本、能直接回答该主张的其他权威原始来源、可靠二手来源；仍不足时才按[公开检索](sources/public-web.md)把搜索标题或列表概要作为受限弱证据。记录实际检索范围、纳排、取得与合格数量、证据层级及停止原因；使用平台工具时还记录查询、排序、时间与后续状态。后台受理不等于空结果，结果读完不等于上游自然耗尽。涉及付费调用时记录实际 Credits 和调用数；用户未设硬上限时按证据增益与费用停止，不搬用开发测试预算。

把错误当成证据缺口：字段不存在、服务失败、链接归属冲突时，先检查是否能从原发布方、可访问副本或其他合适来源核对。不能核对时隔离该证据，重估问题是否仍可回答；弱证据只能缩小缺口，不能伪装成已取得详情，也不把“多来源”本身称作数据完整。

## 3. 分析与综合

- 比较前先统一对象、适用地域和主体、定义、时间、版本与计量口径；不具可比性的资料只并列解释。搜索结果不自动代表总体规模、排名或完整观点；仅有标题或列表概要时遵守弱证据边界。
- 统计观点、经历或事件前先定义分析单位与样本，不同载体和层级分开；标注纳排和选择方式。若计划报告样本内分布，应对预先定义的合格样本全部编码，并显示各组分母。目的性选择只能举例，不能升级为总体发生率或多数判断；多标签合计可超过 100%，非概率样本的占比仅描述该样本。帖子、社媒评论和商品评论是这一通用规则的例子，不是唯一适用对象。
- 区分当事方陈述、用户或受访者经验、原始记录、独立验证和推断；一项指标不能替代另一项结果。缺失值不填零；单次快照不称趋势。
- 先在各来源、主体、群体或时期内解释，再综合共同点、差异和矛盾。综合前核对实体、层级、版本、地域、时期与证据单位。以下仅为例子：产品族资料不能直接归到具体型号，地区样本不能无说明外推其他市场，不同平台互动不可相加成“全网热度”，不同效力或版本的政策文本不能混作现行规则。
- 新增来源要说明它支持、修正、反驳或补充了哪些既有判断。来源更多、记录更多或平台更多不自动提高结论强度；失败或不可用的平台只形成证据缺口，不能计入覆盖。增量研究应区分保持、修正、新增和仍未解决的结论，不把新数据机械附在旧报告后。
- 主张强度与证据匹配：评分数、搜索命中或互动量不代替销量；单一案例不升级为发生率或普遍风险；混杂样本不承担精确对象判断；目的性样本不承担总体比例。比较对象由读者实际面对的选择集合决定；若只比较同系列配置，就按配置比较表述，需要市场竞品结论时再在已认可范围内寻找真正可比对象。
- 主动寻找会推翻初步结论的反例、不同解释、可比对象或条件变化。探索性研究应解释格局、差异和尚未解决的问题；投入决策才需要判定和翻转门槛。不要以“建议下一步调研”代替本轮本可完成的分析。

## 4. 交付前的内部审阅

AI 自己写成品报告，不从内部台账拼章节。逐一复核：用户的主要问题是否得到实质回答；关键对象和来源能否点击；每个重要数字的单位、分母、时间和来源是否匹配；观点是否来自合格样本；有无忽略反证或未满足的方案承诺。复算摘要、正文、表格和图形中的对象数、样本数、分母及关键判断；Markdown 与 HTML 必须一致。若计划包含社媒，检查是否呈现讨论内容与分歧，而不只报播放量或插入几条引文。内部保存原始资料、映射、编码、计算和 QA；成品只保留必要口径、链接和真正影响结论的限制。报告设计见[指导思想](report-design.md)。

交付前按正文逐项确认来源：只有能核实对象、字段、来源和适用范围的 RealTrace MCP 响应被采用，并实际支撑至少一个报告中的事实或分析，才算“使用了 RealTrace MCP 数据”。可用的既存 RealTrace 响应同样算；仅安装、查阅契约、发起调用、产生费用，或得到空值、失败、未核实/已隔离的响应，都不算。混合来源也按是否实际采用合格数据判断，不按来源数量投票。内部记录这个判定和对应主张；对外不展示工具日志或来源审计表。

制作对外报告时，按[报告交付规则](report-delivery.md)核对语言、来源判定、成品标记及链接；HTML 还须检查屏幕和打印可见性。即时回答与内部材料不套用成品标记。

需要复算时可导入[确定性检查函数](../scripts/research_checks.py)：它按稳定 ID 去重、核对 Reddit 父帖链接、识别已见日期占位、对预定且全部编码的样本计数，以及按明确的首年付款次数求总费用。它不检索、不推断抽样代表性、不写报告；不适合当前问题时直接用其他可靠计算办法。纯任务不需为使用脚本而创建数据文件。
