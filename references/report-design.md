# 报告设计指导思想

这是一组帮助 AI 作判断的问题，不是报告目录或写作模板。根据读者的实际问题选择分析视角、证据、统计和表达形式；没有某类数据时，不用长段文字掩盖空缺。商业、政策、技术、社会、组织、事件及其他主题都从同一组通用研究原则出发，再按对象加载专项规则。

## 从问题反推研究

先问：读者想认识对象或关系格局、作比较、理解观点与经验、解释变化或原因、发现机会，还是立即作选择？哪些发现会改变答案？把问题拆到可研究的层级，优先处理影响大、可验证的部分。分析完成后，要综合成与任务相称的答案：格局研究说清主要对象、关系与差异，事件研究说明发生了什么、各方如何解释及适用边界，机制研究区分证据支持与替代解释，决策研究再说明选择及翻转条件。不能把资料列表或“下一步调研”当答案。McKinsey 对结构化问题解决的说明强调问题定义、优先级、方法选择以及最后的综合表达；同时指出结构化方法是创造性判断的支架，不是僵硬流程。[方法来源](https://www.mckinsey.com/capabilities/strategy-and-corporate-finance/our-insights/how-to-master-the-seven-step-problem-solving-process)

## 先界定对象、边界和比较关系

说明研究对象是什么、什么不在范围内、各对象处于哪个层级，以及为什么可以比较。比较集合应来自读者实际面对的选择或待解释关系，而不是由同一个关键词命中的结果拼成。核对对象身份、时间、地域、版本、适用主体、指标定义、计量单位与重叠；无法对齐的资料只并列解释。涉及总量、占比、变化或排名时，先确认分母、基期、覆盖范围和数据是否可加。

例如（以下仅用于说明原则，不是默认分析视角）：两个软件版本只是版本比较，不能自动代表完整技术格局；一项地方政策不能无说明外推全国；一个组织的个案不能变成行业发生率；同一系列的两个 SKU 是配置比较，需要市场竞品结论时还要纳入真正可替代对象。IBISWorld 先定义行业边界再呈现参与者和驱动因素，Euromonitor 提醒不同数据类型、地域与产品层级相加会重复计数；这些来源说明“先对齐范围与口径”的通用原则，不要求其他研究照搬其章节。[边界示例](https://help.ibisworld.com/en/articles/8149882-industry-reports) · [口径示例](https://api-portal.euromonitor.com/user-guide/data-returned-by-api)

研究机会或方案时，从期望结果、现有做法与替代方案、实施条件、成本或负担、风险和反证交叉检验。缺少关键可行性、效果或成本证据时，可以提出有条件的机会，但不能写成已证明的收益。McKinsey 的产品改进研究把客户需要、竞争格局、供应链和实际体验结合起来；这里引用的是多维交叉检验的方法，产品只是示例。[方法示例](https://www.mckinsey.com/industries/industrials/our-insights/the-need-for-speed-accelerating-product-improvement-at-industrials)

## 让证据改变观点

同一主张尽量区分并核对：原始记录显示什么，当事方或利益相关者如何陈述，直接经历或观察说明什么，独立来源验证了什么，哪些反例支持另一种解释。每种来源只回答它能回答的问题；可见度、出现次数、互动、引用量、评分或搜索命中不能自动替代采用、销量、效果、代表性或因果。

对新判断提出“出现什么证据时我会撤回或改写它”。新增来源要说明它支持、修正、反驳还是补充了什么，而不是只增加来源数量。若只能取得标题、列表概要或截断摘要，按[公开检索规则](sources/public-web.md)标为弱证据；它可以提示存在某种公开表述，但不能代替完整原文、精确对象详情或关键判断。

需要统计观点、经历、行为或事件时，说明分析单位、纳排、选取方式、时间与分母。目的性样本可以帮助理解理由和反例，但不能报告总体比例或“多数”。只取一个案例、一个群体或一项内容下的记录时，结论只属于该范围。AAPOR 对内容分析要求说明分析单位、内容来源、抽样和纳排规则，也要求披露 AI 是否参与选择或编码；这一透明度原则不只适用于社媒。[透明度来源](https://aapor.org/standards-and-ethics/transparency-initiative/)

## 综合来源与增量研究

合并来源前，核对它们是否指向同一实体、层级、版本、地域、时期、主体和证据单位；来源相互转述不能伪装成独立交叉验证。新增来源要说明它支持、修正、反驳或补充了哪个判断，失败或不可用的来源只形成缺口。搜索标题等弱证据不会因为多个结果重复而升级为已验证事实。

结论力度由证据决定：单一案例不能升级为发生率或普遍风险，混杂样本不能承担精确对象判断，目的性样本不能承担总体比例，代理指标不能未经论证替代目标结果。例如（仅作说明），ratings 不等于销量、论文中的特定实验结果不自动代表所有实施环境、机构声明不等于独立验证。

增量研究不能只是把新资料追加到旧报告；应辨认哪些原结论保持、哪些被新证据修正、哪些是新增发现、哪些问题仍未解决，再重新综合答案。

## 写给实际读者

先给用户所问问题的直接答案，再用少数最有解释力的比较、分布、关系或案例说明“为什么”和“有什么相反证据”。章节顺序随任务而变；例如（仅作启发），技术路线研究可能先比较实现条件与权衡，政策研究可能先澄清版本、效力和受影响主体，事件研究可能先给时间关系和不同解释，商品或创作者研究则按相应专项指引组织。每张表、图和段落都应回答一个研究问题，不能只是转录字段，也不能为了美观把不可比数据画在一起。

重要对象和关键来源提供可点击原始链接，关键数字旁给适用范围与时间，限制只写会改变读者判断的部分。行动建议用于决策或执行型任务；探索型任务可以用有条件的发现或机会判断收束，不必堆砌“下一步”。

每份对外报告须在正文末尾按[报告交付规则](report-delivery.md)加入简洁的“附：数据来源”，只分组列出实际采用的 MCP 平台和公开资料来源；同一平台或发布方只列一次。不要把它扩展成原始响应、逐条记录、SHA-256、详细来源台账、查询日志、编码台账或 QA 检查。可核验不等于全文堆证：读者应能从正文中的关键对象与链接核对判断，研究者在内部保留完整证据。

对外报告的语言与成品标记按[报告交付规则](report-delivery.md)处理。标记不代替证据与限制，也不应挤占正文；所有结论、附注和来源链接放在尾标之前。

写完后按读者和原问题复读：能否迅速找到主问题的答案、适用对象与时空边界、关键证据、分歧、反证及未解决部分？对象身份、版本、效力、指标定义和适用条件是否与结论一致？复算摘要、正文、表格、图形以及 Markdown 与 HTML 中的对象数、样本数、分母和关键判断；不一致时先修正再交付。这些是审阅问题，不是必备章节。若答案埋在方法和证据清单里，重写正文。
