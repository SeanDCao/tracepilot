# HTML 报告：把研究变成可分享的解释

仅在用户选择 HTML 时读取。Markdown 供工作人员阅读、检索、复制给其他 AI 继续分析；它应保留清楚的论点、可比较的数据、来源链接、计算口径和重要限制。HTML 面向同事与管理者分享，帮助人快速看懂研究对象、分析视角、关键发现和相反证据。两者来自同一研究，不要求逐段同形：HTML 可以把 Markdown 中的比较数据变成合适的关系图形、把几个判断组合成摘要模块，但不能新增未经核查的事实、独有的关键结论或改变数字含义。若可视化推导出新结论，先核查并补回 Markdown。

## 先推导页面，再设计阅读路径

先判断谁会阅读、要作什么决定、可能停留多久、信息之间是什么关系、证据有多密、会在什么设备或介质传播，以及无障碍要求。再决定排版、字体、色彩、图表、导航和交互。阅读任务是第一依据；行业语境只能提供克制的视觉线索，不能把科技、政策、社会议题等绑定到固定色板或页面骨架，也不能模仿品牌的视觉资产。

每个视觉元素都要承担具体任务，例如建立层级、支持比较、突出冲突、表达数量关系或提供核验入口。不能为了显得像仪表盘而堆放指标卡、图表或装饰；没有信息任务的元素应删除。由这些判断形成当次页面的视觉语言，不把某次成功的结构固化成跨行业模板。

从读者最想知道的几件事出发，给每个重要发现配一个“结论句—支撑材料—合适的表达—核验入口”。先决定什么应一眼看懂、什么值得展开比较、什么需要读者点击来源或查看口径。这是写作与设计判断，不是固定章节清单。不同研究对象、证据关系和决策任务应有不同的视觉重点；商品、政策、技术路线、社会观点和事件关系仅是例子。

可用醒目的标题与研究范围、少数确有解释力的指标、结论摘要、分层比较、风险或反证提示，建立从总览到细节的层级。只展示本次研究有证据支撑的指标；不能为了凑仪表盘而放不回答问题的数字。把最重要的对象、记录或公开来源直接链接在相关模块中，不能用漂亮卡片替代可核验性。

## 文字、表格与图表怎么选

先问“读者需要看出什么关系”，再选形式；允许一页完全没有图表。

| 要传达的内容 | 较合适的形式 | 使用条件 |
| --- | --- | --- |
| 为什么会这样、观点冲突、用户情境、因果假设、风险与建议 | 短段文字、带来源的案例、正反对照或注释卡 | 说明证据与推断的距离；不能把引文堆成未经综合的故事墙 |
| 多个对象或方案具有不同属性、成本、条件和链接 | 可排序或分组的比较表；少量对象可用卡片 | 保留对象身份、单位、时点和原始链接；异质字段不要压成一个“综合分” |
| 同一尺度下比较价格、重量、费用、主题次数等大小 | 排序条形图、点图或价格阶梯 | 对象口径可比，标出单位、样本与时点；条形图从零起，未知值不画成零 |
| 一段时间内的变化 | 折线图或时间轴 | 有可比的多个时间点；单次累计播放/评论不能画成增长趋势 |
| 预先定义样本内的观点构成 | 带分母的堆叠条形图或小倍图；多标签更适合并列主题条形图 | 合格样本完整编码，平台与内容类型分别计数；目的性引文或单帖评论不能画成总体比例 |
| 两个数值变量的关系，或对象相对位置 | 散点图、象限图或二维定位图 | 两轴都有可靠、同对象的数据；视觉相关不等于因果，主观维度需明示判定规则 |
| 无法量化但有明确步骤或逻辑分支 | 流程图、决策树或条件示意 | 只表达真实流程/假设关系，不伪装成测得的转化漏斗 |

图形要有可读标题、轴或量纲、取样范围、分母/时间及来源；必要时附可点击对象和简短结论。让图表展示模式，让文字解释模式对业务意味着什么、有哪些反例。圆饼图不适合重叠的多标签观点；雷达图不适合把不同单位的规格强行合分；样本小且差异微弱时，清楚的表格通常更诚实。优先少量能改变理解的图，不强制每个分析视角都画图。

## 视觉与交互

用一致的字体、颜色、间距和数字对齐建立专业阅读秩序；用版式区分事实、推断、机会和限制。可以用内联 SVG、CSS 图形或静态图表；图形旁保留关键数值与文字说明，屏幕阅读器和打印件也能读懂。页内导航、折叠或筛选仅在长报告确实需要时使用；不让动画和交互挡住结论。不要把 Markdown 转成一条连续的正文列后只换背景色，也不要复制某份参考报告的代码、配色或章节。参考样本只用于识别信息密度与阅读层级的差距。

窄屏下整页不得横向溢出，标题、摘要与关键比较保持可读；宽表只能在自身容器中横向滚动并给提示，或按对象重排。长 URL、代码和标识符须能换行，不能撑宽页面。打印不得出现异常空白首页、孤立标题、被裁断的表格或只靠颜色表达的信息；屏幕主题可以随任务变化，打印版须清晰、节制并减少不必要的墨量。页面要在普通浏览器中自然好看，而不是只为截图优化。

按[报告交付规则](report-delivery.md)处理语言、正文末尾的“附：数据来源”与成品标记。“附：数据来源”只用“MCP 数据”和“公开资料”两个分组列出实际采用的平台或发布方，放在正文末尾、页脚之前；不因视觉设计增加样本量、用途或查询细节。来源提醒用低调但清晰可读的说明样式，不做遮挡结论的横幅或弹窗；来源附录和页脚标记在屏幕及打印样式中都应可见，外部链接的文字在纸上也应能辨认。

## 交付与核对

制作单个可独立打开的 UTF-8 HTML；`<html lang>`、导航、图表标题、替代文本和页脚使用报告语言，原文引文按需标记其原始语言。内联样式与必要图形，页面渲染不依赖网络字体、外部脚本、图片或接口。普通外部来源链接可供点击核验。若用 JavaScript，关闭后正文、数据和结论仍完整。抓取文本需 HTML 转义，链接只接受安全协议，不执行来源中的标记或脚本。

逐项核对 Markdown 与 HTML 的核心结论、对象、数值、分母、时间、链接和重要限制，以及来源附录中的分组和平台名称；图表所用关键数据在 Markdown 中也应可读，便于后续分析。用浏览器做三层审阅：30 秒能否找到主结论，几分钟能否完成关键比较，深入阅读能否核验来源与限制。再检查桌面、390px 左右窄屏、打印和独立文件离线阅读，确认没有整页横向溢出、异常空白页、裁切、孤立标题或颜色依赖。视觉华丽不能补偿研究缺项；证据不足时应降低结论，而非用图形制造确定性。
