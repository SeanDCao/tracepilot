# TracePilot 内部研究架构

本文件把核心需求就绪后的研究判断组织为可执行、可保存、可复核的内部蓝图：

`研究目的 → 问题树 → 分析命题 → 证据要求 → 分析方法 → 章节蓝图 → 表达形式`

它适用于需要选取或整合证据并交付研究报告的任务。
它不是新增的用户问卷、固定行业模板或对外交付物，也不改变既有的方案确认、取数、证据和交付规则。
只记录结构化决策与简洁依据，不记录自由展开的思维链。

## 生成、定稿与更新

核心需求就绪且完成初步研究决策审计后，先形成内部研究架构草案，再据此生成现有的一屏研究方案。
若 RealTrace 可能适用，按[研究工作法](workflow.md)完成实时能力探知和证据覆盖映射，再定稿草案中的证据路线与来源边界；此时不抓取业务资料。
面向用户只呈现既有研究方案，不展示完整问题树、命题矩阵或内部状态。

用户认可方案并创建任务目录后，在正式业务取数前把定稿保存为任务内部的 `research-blueprint.md`。
纯唤醒、即时事实问答和不创建研究任务的请求不生成该文件。

取得证据后，按需更新问题状态、工作命题、反证、证据缺口、综合顺序和章节蓝图。
计划内的命题修正、反例纳入、章节合并或表达方式调整属于内部迭代；只有研究目的、来源范围或费用边界实质扩大时，才按既有规则重新征询用户。

## 蓝图的最小结构

`research-blueprint.md` 应简洁记录以下内容；字段可以按任务复杂度合并，但不得遗漏会影响研究方向或结论强度的决定。

### 研究简报

- 研究目的：本次最终要回答什么，以及答案将用于什么。
- 读者用途：谁会使用答案，是理解、比较、解释、探索机会还是作决定。
- 任务类型：对象或格局、比较、观点与经验、变化或事件、原因或机制、机会、决策，或其必要组合。
- 对象与边界：对象身份和层级、比较关系、地域或人群、时期、适用主体、纳入与排除。
- 已确认约束：来源、深度、费用、停止条件和交付形式；明确哪些来自用户、可靠推定或已回显的默认值。

### 问题树

只保留会改变答案的核心问题和子问题，并为其分配稳定的简短编号。

| 字段 | 记录内容 |
| --- | --- |
| 问题 | 可由证据回答的具体问题 |
| 对答案的影响 | 它可能确认、改变或限制什么判断 |
| 依赖 | 需要先解决的对象、定义、事实或其他问题 |
| 回答状态 | 未开始、证据不足、部分回答、已回答或不再适用 |

问题之间应尽量相互区分并覆盖主问题，但不为形式上的穷尽而加入无关维度。

### 命题、证据与方法

每个核心问题记录：

| 字段 | 记录内容 |
| --- | --- |
| 工作命题 | 当前可检验的暂定解释或预期，不得写成既定结论 |
| 可能反证 | 会削弱、推翻或迫使改写命题的事实、案例或替代解释 |
| 合格证据 | 能直接回答该问题的对象、字段、材料类型、口径与证据层级 |
| 证据路线 | 来源分工、获取层级、样本或计算要求、替代来源与已知缺口 |
| 分析方法 | 比较、分类、时间关系、内容分析、机制检验、方案权衡或其他适用方法 |
| 回答状态 | 当前证据支持、反驳、修正了什么，仍缺什么 |

命题用于指导检验，不得让检索只寻找支持材料。
合格证据和方法必须与对象层级、时间、地域、定义、分母及任务用途一致。

### 依赖、综合与翻转条件

- 标明哪些问题必须先解决，避免在对象、版本或口径尚未确认时提前综合。
- 说明综合顺序：先回答哪些决定性问题，再处理差异、反证和条件限制。
- 对重要判断记录决策翻转条件：出现什么证据、边界变化或代价变化时，应撤回、降级或改写结论。
- 无法满足翻转条件所需证据时，把它保留为限制，不制造确定性。

### 章节蓝图

章节不是行业惯例清单，而是问题、证据与读者用途的表达结果。

| 字段 | 记录内容 |
| --- | --- |
| 拟定章节 | 工作标题，可随证据变化 |
| 章节目的 | 本节要让读者理解或决定什么 |
| 对应问题 | 本节回答的一个或多个问题编号 |
| 证据与结论状态 | 可支撑的判断、反证、缺口和结论强度 |
| 表达形式 | 文字、表格、图表、时间轴、案例或必要组合 |

每个正式章节必须回答一个或多个研究问题。
默认综合顺序是“直接答案 → 决定性分析 → 分歧与反证 → 条件化综合”，但可按读者任务调整具体章节位置。
证据不足的章节应删除、合并或降低结论强度，不能用篇幅、图表或视觉设计掩盖缺口。

用户提供参考模板时，先把已有章节映射到研究问题和证据要求。
结构合理且覆盖任务的部分直接继承；只调整冲突、重复、无证据支撑或遗漏决定性问题的部分，不为显示方法而强制重写。

Markdown 与 HTML 使用同一份研究蓝图。
HTML 可以重新设计阅读路径和表达形式，但不能另建研究问题、改变证据边界或产生 Markdown 中不存在的关键主张。

### 简洁决策记录

只在决定会影响范围、证据路线、分析方法、结论强度或章节结构时，记录“决定、简洁依据、影响和更新时间”。
不要保存逐步联想、自我对话、被舍弃的自由推演或其他自由展开的思维过程。

## 按任务选择分析方法

以下方法是内部路由选项，不是固定报告目录；只选择能回答本次问题的部分。

- 对象或关系格局：界定实体、层级、角色、关系和边界，解释主要差异与缺口。
- 比较：先对齐对象、指标、时间、地域、版本、单位和适用条件，再按读者实际标准比较。
- 观点与经验：定义分析单位、样本和纳排，区分主体、载体与语境；只有合格样本才计算分布。
- 变化或事件：核对时间线、版本、行为主体、影响范围和不同解释，区分同时发生与可支持的因果关系。
- 原因或机制：提出可检验机制和替代解释，主动寻找反证；证据不足时只写相关、条件或假设，不作因果过度推断。
- 机会探索：交叉检查期望结果、现有做法与替代方案、未解决负担、采用条件、风险和反证。
- 具体决策：明确备选项、标准、权衡、约束与翻转条件，让建议能够追溯到证据。

## 内外边界

- 对外研究方案仍保持一屏摘要，不增加确认步骤，不展示完整内部矩阵。
- `research-blueprint.md`、问题树、命题—证据映射、内部状态和简洁决策记录不进入对外报告或“附：数据来源”。
- 不保存自由展开的思维过程；只保存他人能够复核的研究决定、依据、状态和边界。
- 专项模式可以补充分析维度、对象约束和证据注意事项，但不直接决定章节目录。
- 章节数、问题数、证据数和图表数均由任务决定，不设固定配额。
